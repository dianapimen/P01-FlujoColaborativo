## Flujo de trabajo
Este proyecto sigue un flujo de trabajo basado en Git Flow simplificado:

1. Issue
   - Se crea una issue para cada tarea o corrección.
   - Se define el objetivo, alcance y criterios de aceptación.
2. Rama corta
   - Se crea una rama dedicada para resolver la issue.
   - Se usa un nombre claro y corto, por ejemplo: feature/nombre-tarea o fix/correccion-bug.
3. Pull request
   - Cuando la tarea está lista, se abre un pull request describiendo los cambios realizados.
4. Revisión
   - El código es revisado por otro integrante del equipo.
   - Se validan criterios de calidad, funcionamiento y consistencia.
5. Merge
   - Una vez aprobada la revisión, se realiza el merge a la rama principal correspondiente.

## Contribución del equipo
- Cada integrante debe registrar su contribución en la carpeta de documentación correspondiente.
- Se recomienda mantener mensajes de commits claros y descriptivos.
- La colaboración se realiza mediante ramas separadas y revisión mediante pull requests.
